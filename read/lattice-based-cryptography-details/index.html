格密码

本篇详解的复核与目录元数据验收分别记录；全库仍在逐项建设。

原理与机制为什么重要应用与实例边界与攻击面历史与背景逐步示例与核验参考出处

原理与机制

术语：格密码（Lattice-based Cryptography）。FIPS 203 定义 KEM 为「a cryptographic scheme that, under certain conditions, can be used to establish a shared secret key between two communicating parties」，由 KeyGen、Encaps 与确定性 Decaps 三个算法组成，并说明「The security of ML-KEM is based on the presumed hardness of the so-called Module Learning with Errors (MLWE) problem」。同族的 FIPS 204 对 ML-DSA 采用带环参数的 MLWE 问题（副本把那个参数印成丢失的数学字形，故只转述不复引）加上称为 SelfTargetMSIS 的 MSIS 非标准变体。

为什么重要

标准先把底层公钥加密 K-PKE 经 Fujisaki-Okamoto 变换转成 KEM，并说明「ML-KEM is believed to satisfy so-called IND-CCA2 security」；同时警告「The scheme K-PKE is not IND-CCA2-secure and shall not be used as a stand-alone scheme」。Announcement 的 §10 记录「ML-KEM is the name given to the algorithm in this standard derived from CRYSTALS-KYBER」。

应用与实例

三组参数 ML-KEM-512、ML-KEM-768、ML-KEM-1024 分别声称处于安全类别 1、3、5，表 2 对应要求的随机数发生器强度为 128、192、256 位；标准还写明「NIST recommends using ML-KEM-768 as the default parameter set」。

边界与攻击面

标准要求解密前的输入检查与「Destruction of intermediate values」。若密文解密校验不通过，算法执行 implicit rejection：原文该步那句在本副本里把 k、c、z 三个变量印成了丢失的数学字形，因此只转述不复引——k 的值改为 c 与存于 ML-KEM 私钥中的随机值 z 的哈希；并且那个秘密标志位「returning the value of the flag as an output in any form is not permitted」。表 1 给出三组参数约 2 的负 138.8、164.8、174.8 次方的解密失败率。

历史与背景

NIST IR 8547（2026 年 10 月）在 §2.1.2 记录 ML-KEM 源自 CRYSTALS-KYBER 提交，在 §3.2 说明迁移初期的混合方案「typically designed to remain secure if at least one of the component algorithms is secure」，并在 §4 规定量子脆弱的公钥密码在 2030 年后弃用、2035 年后不得在 NIST 标准与指南下使用；FIPS 203 与 FIPS 204 均于 2024 年 8 月 13 日发布。
