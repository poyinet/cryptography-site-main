SM9 标识密码算法

本篇详解的复核与目录元数据验收分别记录；全库仍在逐项建设。

原理与机制为什么重要应用与实例边界与攻击面历史与背景逐步示例与核验参考出处

原理与机制

标准：SM9 标识密码算法（SM9 Identity-Based Cryptography Algorithm）。### 配对与系统参数

SM9 使用双线性配对 e:G1×G2→GT。密钥生成中心持有主私钥 ks，计算系统公钥 Ppub=ksP2。用户标识 ID 与 hid 经 H1 映射到标量，用户私钥为

d_{ID}=ks·(H1(ID‖hid,N)+ks)^{-1} mod N·P1。### 签名

签名者取随机 r，计算 w=e(P1,Ppub)^r、h=H2(M‖w,N)、l=(r−h) mod N，若 l=0 重取；签名 S=l·d_ID，输出 (h,S)。### 验证与加密

验证计算 u=e(S,H1(ID‖hid,N)P2+Ppub)，w=u·g^h，检查 H2(M‖w,N)=h。加密/KEM 先把标识映射为 Q=H1(ID‖hid,N)P1+Ppub，取随机 r，C1=rQ，共享值 g=e(Ppub,Q)^r，再经 KDF 派生密钥。

为什么重要

SM9 把公钥直接绑定到标识，不需要证书链；密钥生成中心负责派生用户私钥。它适合邮件、专网与需要简化证书管理的场景。SM9 是标识密码；SM2 是证书式椭圆曲线公钥算法，SM4 是分组密码。SM9 的信任根在 KGC，和 SM2 的证书信任模型不同。

应用与实例

1.系统参数：使用标准曲线、配对与哈希函数，固定 hid 与标识编码。2.密钥派生：KGC 认证标识后派生 d_ID，私钥安全下发并可更新。3.签名/加密：每次取新鲜随机 r；加密先 KEM 再对称加密。4.验证：检查配对结果、h/S 范围与标识绑定。### 不能怎么用

不能把 KGC 当无信任第三方；不能跨 hid/参数混用密钥；不能把 SM9 当抗量子算法。

边界与攻击面

1.密钥托管：KGC 能派生任何用户私钥，必须作为信任根审计；主密钥泄露会瓦解全系统。2.配对实现：配对运算的时序、缓存与故障可泄漏私钥或伪造签名。3.标识与参数：hid、曲线、哈希或编码不一致会导致互操作失败或跨域攻击。4.协议层：不绑定标识、不检查 C1 与 KDF 输出，可能遭替换或解密错误。

历史与背景

SM9 于 2016 年进入 GM/T 0044 序列，2020 年发布 GB/T 38635.1/2—2020；ISO/IEC 18033-5 也收录标识密码方案。RFC 8998 不覆盖 SM9。SM9 的签名、密钥交换、KEM 与加密分属不同部分；实现以所声明部分与版本为准。
