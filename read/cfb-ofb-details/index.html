CFB/OFB 模式

本篇详解的复核与目录元数据验收分别记录；全库仍在逐项建设。

原理与机制为什么重要应用与实例边界与攻击面历史与背景逐步示例与核验参考出处

原理与机制

术语：CFB/OFB 模式（CFB/OFB Modes）。CFB 的定义句在 SP 800-38A 的 6.3 节：「The Cipher Feedback (CFB) mode is a confidentiality mode that features the feedback of successive ciphertext segments into the input blocks of the forward cipher to generate output blocks that are exclusive-ORed with the plaintext to produce the ciphertext, and vice versa.」关键词是密文段反馈——反馈的是密文，因此解密侧要把前一段密文作为输入块。

为什么重要

OFB 与 CFB 的分工写在 6.4 节的定义句里：「The Output Feedback (OFB) mode is a confidentiality mode that features the iteration of the forward cipher on an IV to generate a sequence of output blocks that are exclusive-ORed with the plaintext to produce the ciphertext, and vice versa.」差别就在迭代对象：OFB 只迭代自己的输出、与密文无关，因此该节说明在已知 IV 的前提下输出序列可在明文到达之前生成——这也是它与 CFB 的反馈链最根本的区别。

应用与实例

用法上两模式对 IV 的要求并不相同，且都在留存件里：CFB 侧「The CFB mode requires an IV as the initial input block.The IV need not be secret, but it must be unpredictable」；OFB 侧则要求 IV 是一个 nonce，即在该密钥下每次执行都必须唯一。CFB 另引入段长参数 s，该建议说明这个值有时并入模式名（如 1-bit、8-bit、64-bit、128-bit CFB 这些写法就印在同节）。

边界与攻击面

失效条件在 6.4 节写得最直白：「The OFB mode requires a unique IV for every message that is ever encrypted under the given key.If, contrary to this requirement, the same IV is used for the encryption of more than one message, then the confidentiality of those messages may be compromised.」同段接着给出机理：若其中任一消息的第 j 个明文块已知，就能由该消息的第 j 个密文块推出正向密码的第 j 个输出，从而危及其他消息——注意原文的条件句用的是可能被危害，而不是必然。

历史与背景

版本事实（按项目口径写在引号外）：留存件首块把文档标为 NIST Special Publication 800-38A、Recommendation for Block Cipher Modes of Operation: Methods and Techniques，作者行印作 Morris Dworkin；版本行作 2001 Edition，而计算机安全分会的前置页日期印为 December 2001，留存件首块又是两栏排版、标题行与版本行在同一物理行上交错，因此这些事实只作转述、不作引用。该建议还在附录里逐模式给出测试向量（命名形如 CFB1-AES128）。该条目只登记这些印刷事实。

术语小词典

CFB 模式
把连续密文段反馈进正向密码输入块的机密性模式。
OFB 模式
对 IV 迭代正向密码、用输出块与明文异或的机密性模式。
forward cipher
两模式共用的加密方向函数（解密不需要逆密码）。
IV
CFB 要求不可预测；OFB 要求是 nonce，即同密钥下每次执行唯一。
s
CFB 的段长参数（以比特计；该建议说明该值有时并入模式名）。
output block
正向密码产生的块，与明文异或得到密文。
