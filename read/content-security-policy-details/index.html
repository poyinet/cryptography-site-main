内容安全策略（CSP）

本篇详解的复核与目录元数据验收分别记录；全库仍在逐项建设。

原理与机制为什么重要应用与实例边界与攻击面历史与背景逐步示例与核验参考出处

原理与机制

术语：内容安全策略（CSP）（Content Security Policy (CSP)）。内容安全策略是一套让网页开发者控制页面可以获取或执行哪些资源、并作出其他安全相关策略决定的机制。

为什么重要

CSP 用于降低内容注入漏洞（如跨站脚本）的风险，并减少应用执行时的权限，从而限制攻击者的脚本能做什么。

应用与实例

策略通过 Content-Security-Policy 响应头或 meta 元素下发，使用 default-src、script-src 等指令限制来源；report-to/report-uri 用于报告违规。

边界与攻击面

CSP 不是完整的 XSS 防御：过于宽松的指令、允许内联脚本或 eval 会削弱保护；report-only 模式只报告不拦截，不等于实际执行策略。策略需要按页面和威胁模型审查。

历史与背景

CSP Level 3 由 W3C Web Application Security Working Group 以 Recommendation track 发布工作草案，继续扩展指令和报告机制。

定义、正例与反例

内容安全策略（CSP）在协议与 PKI中是基础术语，定义先给上位概念，再给区别特征与可观察判据。

正例必须落在外延内；反例必须刚好跨过边界，说明它缺哪一个必要条件，而不是只给同义词。

没有标准定义时用权威教材，但仍标出版本与适用范围；术语条目不以“大家都知道”作为定义依据。

与相邻概念的辨析

内容安全策略（CSP）与相邻术语的区别不在名称，而在定义域与判据：前者要求哪些必要条件、排除哪些对象、在哪个标准或教材中有定义。

辨析时先找上位概念，再找区别特征，最后给反例；只给同义词或英文缩写不算定义。若两个术语在文献中混用，正文并列保留差异，不强行合并。
