协议与 PKI：子主题领域定义

基础专题不等于相关实体的完整详解验收。

原理与机制为什么重要应用与实例边界与攻击面历史与背景参考出处

原理与机制

领域：协议与 PKI。

安全协议把密码原语编排成参与方之间的消息流程，并用证书、身份与新鲜性机制抵抗重放和中间人；协议错误常比原语弱点更致命。

本页把该领域尚未单独成文的 7 个子主题集中结算：

  • CBOR 与 COSE 编码（cbor-cose）：CBOR 是紧凑二进制数据模型，COSE 在其上定义签名、加密与 MAC 对象，常用于物联网与 FIDO。
  • Dilithium（dilithium）：Dilithium（ML-DSA）是基于格的签名标准，签名与公钥较大但 verification 简单，已进入 NIST 后量子标准。
  • DTLS 数据报传输安全（dtls）：DTLS 把 TLS 握手与记录层搬到 UDP 上，为实时媒体与物联网提供数据报安全，必须处理丢包与重放。
  • HTTP CONNECT 隧道（HTTP CONNECT tunnelling）：HTTP CONNECT 让客户端通过代理建立一条端到端隧道，代理只转发字节流；认证与目标白名单是它的安全边界。
  • 媒体会话安全（media session security）：媒体会话安全关注 SRTP、DTLS-SRTP 与密钥协商，重点是媒体流的机密性、完整性与同步。
  • Network Access Authentication（network-access-authentication）：网络接入认证（EAP/802.1X）在设备入网前完成身份与策略检查；凭证保护与隧道方法决定其实际强度。
  • TLS 握手（tls）：TLS 握手协商算法与密钥、验证证书并建立记录层密钥；配置、证书验证与版本降级是主要失败点。

领域规模

本领域在目录中有 100 条登记条目，覆盖 11 个时代组。类型分布：algorithm 0，attack 1，theorem 0，protocol 38，standard 4，machine 0，person 0，event 6，term 47。这不是“全部已完成长文”的计数，而是可检索、可复核的目录节点数；每个节点是否达到机制深度，要看它自己的正文与来源。

为什么重要

把这些子主题放在同一页，是为了先建立领域边界与最小定义，再决定哪些需要独立深度条目。它避免用空链接占位，也避免把“有一个名字”误当成“已经解释清楚”。

关键争论

  1. 定义边界：领域名是检索标签，不是单一理论。把相邻条目合并会掩盖假设、模型与攻击能力的差异。
  2. 安全边界：目录登记与实现安全不是一回事；标准条款、参数与侧信道暴露必须分别核对。
  3. 历史叙事：人物、机构与事件的纪念性叙述不能替代一手档案，年代与优先权仍需逐条核验。

边界与攻击面

边界：本页是领域级的子主题结算页，不是每个子主题的完整论文。一行定义只负责“它属于什么、解决什么问题”，不替代标准、教材或原始论文；后续若建立独立条目，必须重新做双语正文与证据复核。

不要混入

  • 不要把领域页当成该领域所有条目的完整论文。
  • 不要把目录登记数当成“已核证结论数”。
  • 不要把历史条目中的纪念性叙述当成本领域的技术证明。
