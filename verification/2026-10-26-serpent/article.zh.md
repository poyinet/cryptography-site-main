# Serpent：128 位 32 轮 AES 候选 SP 网络

## principle

**算法**：Serpent 分组密码（Serpent）。Serpent 是 128 位分组密码：32 轮 SP 网络，明文视为四个 32 位字，密钥支持 128/192/256 位（最长 256 位），共有 33 个 128 位子密钥 K0..K32。本文采用论文第 3 节的 bitslice 描述：明文直接作为 B0，不做初始置换 IP；32 轮中的前 31 轮依次做密钥异或、S-box 和线性变换 LT，最后一轮用 S7 并把结果与 K32 异或：

```text
B0 = P
for i = 0..30:
  B_{i+1} = LT(S_{i mod 8}(B_i XOR K_i))
B32 = S7(B31 XOR K31) XOR K32
C = B32
```

论文的标准描述另有初始置换 IP 和最终置换 FP。它们没有密码学意义，只是把数据与标准实现的位序对齐；bitslice 描述不需要它们。标准模式中要计算 Khat_i = IP(K_i)，bitslice 模式直接使用 K_i。本文的实现和向量都使用 bitslice 描述，因此不存在 IP/FP 这一步。轮函数每轮只用一个 4 位 S-box，但在 bitslice 模式下同时作用于 32 个位置：四个 32 位字 X0..X3 是四个位平面，第 j 个 S-box 的输入是 X0、X1、X2、X3 的第 j 位组成的 4 位值，输出再写回四个位平面的第 j 位。S-box 按 S0、S1、…、S7 循环使用，第 i 轮用 S_{i mod 8}。线性变换 LT 对四个 32 位字做以下运算（`<<<` 是 32 位循环左移，`<<` 是逻辑左移）：

```text
X0 = X0 <<< 13
X2 = X2 <<< 3
X1 = X1 XOR X0 XOR X2
X3 = X3 XOR X2 XOR (X0 << 3)
X1 = X1 <<< 1
X3 = X3 <<< 7
X0 = X0 XOR X1 XOR X3
X2 = X2 XOR X3 XOR (X1 << 7)
X0 = X0 <<< 5
X2 = X2 <<< 22
```

八个 4 位 S-box 的输入 0..15 对应输出如下：

```text
S0 = 3 8 F 1 A 6 5 B E D 4 2 7 0 9 C
S1 = F C 2 7 9 0 5 A 1 B E 8 6 D 3 4
S2 = 8 6 7 9 3 C A F D 1 E 4 0 B 5 2
S3 = 0 F B 8 C 9 6 3 D 1 2 4 A 7 5 E
S4 = 1 F 8 3 C 0 B 6 2 5 4 A 9 E 7 D
S5 = F 5 2 B 4 A 9 C 0 3 E 8 D 6 7 1
S6 = 7 2 C 5 8 4 6 B E 9 1 F D 3 A 0
S7 = 1 D F 0 E 8 2 B 7 4 C A 9 3 5 6
```

这些 S-box 是 4 位双射，具有以下性质：任意差分特征的概率至多 1/4，一位输入差分不会产生一位输出差分；线性特征的概率在 1/2±1/4 之间，单个输入位与单个输出位的线性关系在 1/2±1/8 之间；输出位关于输入位的非线性阶数为最大值 3。它们不是任意挑选的：论文说明 S-box 由 32 行 DES S-box 出发，用类似 RC4 的交换过程生成，初始字符串是 "sboxesforserpent"，满足上述差分/线性条件后才被保留。Serpent-0 直接使用 DES 的 S-box；Serpent-1 改用这组生成 S-box，并微调了密钥调度。密钥调度把用户密钥补齐到 256 位：若密钥短于 256 位，在其最高有效端追加一个 1 位，再补零到 256 位。例如 128 位密钥在位置 128 置 1，192 位密钥在位置 192 置 1。补齐后的 256 位按小端序写成八个 32 位字 w[-8..-1]，然后计算 132 个 prekey：

```text
phi = 0x9E3779B9
w[i] = (w[i-8] XOR w[i-5] XOR w[i-3] XOR w[i-1] XOR phi XOR i) <<< 11
```

i 取 0..131。随后把每四个连续 prekey 通过一个 S-box 变换成四个 32 位子密钥字：

```text
K_i = S_{(3-i) mod 8}(w[4i], w[4i+1], w[4i+2], w[4i+3])
```

i 取 0..32，得到 33 个 128 位子密钥。注意 K0 用 S3，K1 用 S2，K2 用 S1，K3 用 S0，K4 又回到 S7，依此类推。S-box 在这里同样是 bitslice 作用：四个 32 位字的同一比特位置构成一个 4 位输入。字节序是小端：第一个明文字节进入 word0 的最低有效字节，「bit 0 is the least significant bit of」word0（bit 0 是 word0 的最低位）；外部通常把 128 位块写成 32 个十六进制数字。本文的 NESSIE 向量按通常的字节顺序打印，实现按小端装入四个 32 位字后与这些十六进制逐字匹配；若把四个字按大端解释，非零向量会得到不同结果。解密使用逆 S-box、逆线性变换和逆序子密钥：

```text
state = C
state = state XOR K32
state = InvS7(state)
state = state XOR K31
for i = 30..0:
  state = InvLT(state)
  state = InvS_{i mod 8}(state)
  state = state XOR K_i
P = state
```

逆 LT 按正变换的逆序执行：先右旋 X2 22 位、X0 5 位，撤销 X2 的异或，撤销 X0 的异或，再右旋 X3 7 位、X1 1 位，撤销 X3 与 X1 的异或，最后右旋 X0 13 位、X2 3 位。教学实现直接按键级顺序写出这些步骤，并用 32 位掩码保证结果。Serpent 的 bitslice 设计允许单个 128 位块用 32 位处理器并行计算 32 个 S-box 实例，而不是像传统 bitslice DES 那样必须同时加密 64 个块。这是它能在常见工作模式下保持高速的原因；论文的 SP 网络结构、S-box 选择和 LT 都是围绕这一点设计的。

## why

Serpent 的设计目标是保守、可分析、在 32 位处理器上高效，并且比三密钥 3DES 更安全。论文设定的块长是 128 位，密钥可以是 128、192 或 256 位，轮数是 32。设计者认为 16 轮 Serpent 已经与三密钥 3DES 相当，但 AES 可能在标准位置和遗留系统中使用很多年，因此选择 32 轮来留出更大的安全边际。安全性分析给出了具体的保守界：6 轮差分特征的概率至多 2^-58，24 轮特征至多 2^-232；28 轮线性特征的分析也给出类似量级；论文进一步猜想最佳 28 轮差分的概率不高于 2^-120。设计者用比完整 32 轮短 8 轮和 4 轮的 24/28 轮特征做分析，并称没有发现有用的捷径攻击；他们认为最好的攻击仍是穷举密钥，128/192/256 位密钥分别对应 2^128、2^192、2^256 的工作量。这些是 1998 年设计者的分析结论，不是对全部攻击模型的形式化证明。论文第 2.1 节给出的 S-box 性质是：差分特征概率至多 1/4，不存在一位输入差分能产生「to a one-bit output difference」（一位输出差分）的情形；线性特征概率在 1/2±1/4 之间，一位对一位的线性关系在 1/2±1/8 之间；非线性阶数为 3。这些性质使每一轮至少有一个活跃 S-box，并在后续轮中迅速扩散。S-box 由 DES 的 32 行 S-box 经确定性交换生成，而不是随机表；这既是为了避免后门质疑，也是为了在保持差分/线性性质的同时减少硬件门数。性能方面，论文报告在 133 MHz Pentium/MMX 上，32 轮 bitslice 实现达到 9,791,000 bit/s，约 1738 周期/块，与同一机器上的优化 DES 实现（9,824,864 bit/s）大致相同；「keeping the subkeys in a fixed array」（把子密钥放进固定数组）后达到 10,281,124 bit/s，约 1656 周期/块。论文估计在 200 MHz Pentium 上约为 14.7 Mbit/s。这些是 1998 年的实现数据，不是今天平台的性能承诺。Serpent 是 NESSIE 项目验证过测试向量的算法之一，也是五种 AES 最终候选之一；它没有被选为 AES。作者页面称 Serpent 已完全进入公有领域，不施加使用限制；页面同时说明优化实现按 GPL 发布，尽管旧的「comments in the code still say otherwise」（代码里的注释仍说另有说法）。使用具体代码时仍应以实际许可文本为准。从教学角度看，Serpent 的价值在于：它把 4 位 S-box、位平面并行、线性变换和 256 位密钥扩展组合成一个结构清晰的 SP 网络；同时它的密钥补齐规则（追加 1 位而不是简单补零）和 bitslice 表示是常见的实现错误来源。

## used

NESSIE 验证向量按密钥长度分为 128、192、256 位三套文件，每套的 Set 1 分别有 128、192、256 条向量，恰好每条对应一个密钥位翻转；Set 2 是零密钥、变化明文；Set 3 是密钥与明文使用相同的重复字节；Set 4 是两组固定密钥/明文。本文完整复现了：

- 三套 Set 1 的全部 576 条向量（128+192+256），逐条加密并解密；
- 每条 Set 1 向量的 “Iterated 100 times” 结果，以及每条密钥长度 vector#0 的 “Iterated 1000 times”；
- 三套 Set 2 的前 32 条、Set 3 的前 32 条和 Set 4 的全部 2 条（合计 198 条）。```text
128 位，Set 1 #0：

P = 00000000000000000000000000000000
C = 264E5481EFF42A4606ABDA06C0BFDA3D

128 位，Set 3 #0：
K = 00000000000000000000000000000000

128 位 Set 1 #0 连续加密 100 次的结果是 EFE6F058D74E357A1CA935D35E0E4F24，与 NESSIE 文件一致；192 位和 256 位对应结果也分别匹配。Set 2 #0 使用全零密钥、明文 80000000000000000000000000000000，密文是 A3B35DE7C358DDD82644678C64B8BCBB，用来检查零密钥下的明文扩散。192 位和 256 位 Set 1 vector#0 的 100 次迭代结果分别是 B083CEAE24F090E4F24E743F1D47BFC2 和 739E0148971FD975B585EAFDBD659E2C。本文按论文公式为 128 位密钥 80000000000000000000000000000000 计算出的第一个子密钥 K0 是 6F539CD2 A7A3A3CE D29591ED 8EDF7292。这个中间值论文没有直接列出，是由密钥补齐、prekey 递推和 S3 变换算出的；它通过全部 NESSIE 向量的密文间接校验。Linux 内核 CryptoAPI 包含 Serpent 实现（crypto/serpent_generic.c），文件头标注版权 2002 Dag Arne Osvik，并说明密钥「to the maximum of 256 bits before round key generation」（在生成轮密钥前补齐到 256 位）、允许最长 256 位。这证明 Serpent 在通用操作系统的加密接口中可用；它不证明内核推荐 Serpent，也不证明任何协议标准采纳了它。

## broken

Serpent 的安全结论必须限定在论文第 5 节的分析范围内。6 轮差分特征 ≤2^-58、24 轮 ≤2^-232、28 轮差分猜想 ≤2^-120，都是设计者用保守模型得到上界或猜想，不是对 32 轮 Serpent 的完整形式化证明。「there is no indication of any useful shortcut attack」（没有发现有用的捷径攻击）是 1998 年的分析结论，不等于未来不会出现新的密码分析；本文不引用未经核实的第三方攻击来宣称 Serpent 已被攻破或绝对安全。工作模式方面，128 位块在 CBC/CFB 下加密约 2^64 个块后，预期出现相同密文块，攻击者可以利用这一点推导明文关系；密钥碰撞攻击的复杂度约为 2^(k/2)。这些性质适用于所有 128 位块密码，不是 Serpent 独有的缺陷。实际协议应在远早于 2^64 个块之前更换密钥，并避免把分组密码直接当哈希或 MAC 使用。实现层面，Serpent 的 S-box 和 LT 通常用查表或位运算实现；查表会带来缓存和时序侧信道风险，位切片实现则对寄存器压力和编译器优化敏感。本文的教学实现用普通 JavaScript 数组和 32 位位运算，不是常量时间实现，也没有掩码、密钥隔离或故障检测，不能用于保护真实数据。部署范围需要区分：NESSIE 验证向量只证明实现与规范一致，不证明安全性；Linux 内核提供 Serpent 实现不等于标准采纳或安全推荐；FIPS 197 只规定 AES（Rijndael），Serpent 不是 FIPS 197 算法。Serpent 只定义分组密码，不提供工作模式、IV 管理、填充、完整性保护、密钥协商或侧信道防护。最后，本文的 576 条 Set 1 向量加上 Set 2/3/4 的抽样都来自同一组作者提供的 NESSIE 文件。它们能强有力地检查字节序、密钥补齐、子密钥和轮函数，但不能替代密码分析。

## history

Serpent 由 Ross Anderson、Eli Biham 和 Lars Knudsen 设计。第一版 Serpent-0 在 1998 年的 Fast Software Encryption（FSE'98）会议上发表，直接使用 DES 的 S-box；随后设计者为了 AES 提交改进了算法：使用新生成的 8 个 S-box、微调密钥调度，并把轮数保持为 32。这个版本称为 Serpent-1，也就是通常说的 Serpent。论文说明 Serpent-0 使用 DES S-box 是为了借助已被长期研究的差分/线性性质，并让公众相信设计者没有植入陷门；Serpent-1 的 S-box 则用确定性的 RC4 类交换过程从 32 行 DES S-box 生成，初始字符串为 "sboxesforserpent"，满足条件后才保留。这样既保留了可分析性，又改善了差分/线性界。1998 年，Serpent 作为 AES 候选算法提交。作者页面称 Serpent 是五种 AES 最终候选之一；AES 最终选择了 Rijndael，并在 2001 年 11 月 26 日发布 FIPS 197。FIPS 197 在 2023 年 5 月 9 日更新为 FIPS 197-upd1；更新不改变 Serpent 未被选为 AES 的事实。作者页面称 Serpent 在 1998 年 8 月 21 日的 AES 会议上宣布进入公有领域，不施加使用限制；页面同时说明提交包中的优化实现现在按 GPL 发布，尽管代码注释仍写旧声明。使用具体代码或许可文本时，应以实际文件为准。Serpent 后来出现在 Linux 内核中；crypto/serpent_generic.c 是 Dag Arne Osvik 在 2002 年写的实现。这些实现说明 Serpent 作为一种分组密码仍可使用，但不改变它不是 AES 标准的事实。
