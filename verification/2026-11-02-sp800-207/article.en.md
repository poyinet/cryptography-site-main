# Zero Trust Architecture (SP 800-207)

## principle

**Standard**: Zero Trust Architecture (SP 800-207) (零信任架构（SP 800-207）). The first abstract sentence places the term: "Zero trust (ZT) is the term for an evolving set of cybersecurity paradigms that move defenses from static, network-based perimeters to focus on users, assets, and resources." The second names the architecture: "A zero trust architecture (ZTA) uses zero trust principles to plan industrial and enterprise infrastructure and workflows." The working assumption follows: "Zero trust assumes there is no implicit trust granted to assets or user accounts based solely on their physical or network location (i.e., local area networks versus the internet) or based on asset ownership (enterprise or personally owned)." Section 1 adds: "A zero trust architecture (ZTA) is an enterprise cybersecurity architecture that is based on zero trust principles and designed to prevent data breaches and limit internal lateral movement." The two definitions work at different levels: the first moves the focus from the network perimeter onto users, assets and resources, the second places ZTA as an enterprise cybersecurity architecture and states its aim; the third abstract sentence fixes the condition on which trust is granted, for which location and ownership are no longer reasons.

## why

The motive is the network trend that dissolves the boundary: "Zero trust is a response to enterprise network trends that include remote users, bring your own device (BYOD), and cloud-based assets that are not located within an enterpriseowned network boundary." Section 1 says why perimeter defences fail: "Perimeter-based network security has also been shown to be insufficient since once attackers breach the perimeter, further lateral movement is unhindered." and states the adversary assumption: "Zero trust security models assume that an attacker is present in the environment and that an enterprise-owned environment is no different--or no more trustworthy--than any nonenterprise-owned environment." Section 2 records the shift of focus: "Zero trust focuses on protecting resources (assets, services, workflows, network accounts, etc.), not network segments, as the network location is no longer seen as the prime component to the security posture of the resource." The four sentences form one argument: the perimeter loses meaning first, because assets no longer sit inside enterprise networks; its failure costs unhindered lateral movement; so the model assumes an adversary already in the environment, and protection is decided per resource rather than per network segment.

## used

What the document sets out first are seven basic tenets, worded as design principles rather than mandates: "A zero trust architecture is designed and deployed with adherence to the following zero trust basic tenets:", the first being "All data sources and computing services are considered resources." Section 2 adds a general requirement: "Overall, enterprises need to develop and maintain dynamic risk-based policies for resource access and set up a system to ensure that these policies are enforced correctly and consistently for individual resource access requests." and advises against inferring later requests from one login, in should-not terms rather than a prohibition: "This means that an enterprise should not rely on implied trustworthiness wherein if the subject has met a base authentication level (e.g., logging into an asset), all subsequent resource requests are assumed to be equally valid." Section 3 places the duties on logical components — the policy engine, "This component is responsible for the ultimate decision to grant access to a resource for a given subject.", and the enforcement point, "This system is responsible for enabling, monitoring, and eventually terminating connections between a subject and an enterprise resource." — while declaring its own status: "Note that this is an ideal model showing logical components and their interactions."

## broken

The document describes models and considerations, not a product or a plan. The abstract says: "This document contains an abstract definition of zero trust architecture (ZTA) and gives general deployment models and use cases where zero trust could improve an enterprise's overall information technology security posture." The Audience section adds: "It is not intended to be a single deployment plan for ZTA as an enterprise will have unique business use cases and data assets that require safeguards." Section 1 keeps the principles framing: "ZT is not a single architecture but a set of guiding principles for workflow, system design and operations" and "Transitioning to ZTA is a journey concerning how an organization evaluates risk in its mission and cannot simply be accomplished with a wholesale replacement of technology." Section 5 is explicit that risk is not removed: "No enterprise can eliminate cybersecurity risk." and names a new concentration of it: "Any enterprise administrator with configuration access to the PE's rules may be able to perform unapproved changes or make mistakes that can disrupt enterprise operations." The self-descriptions accumulate: the document supplies definitions and models, not a deployment plan, and claims no elimination of risk — it even lists the decision components themselves as an attack surface.
