Random self-reduction

Principles

Theorem: Random Self-Reducibility (随机自归约). ### Randomize a worst-case instance

Let f be a one-way function. If a polynomial-time algorithm R exists such that for every x it samples r and outputs y=R(x;r), where y’s distribution is independent of x (usually close to uniform), and given f(y) and r one can recover f(x) in polynomial time, then f is random self-reducible. Hence: if f is hard on average random instances, it is hard on every instance. ### Discrete logarithm

In a cyclic group G of order q with generator g, let y=g^x. Choose r←Z_q and compute y' = y·g^r = g^{x+r}. If an oracle A returns the discrete log x' of y', then x = x'−r mod q. y' is uniform in G and independent of y; one random-instance answer recovers the original. ### RSA blinding

For an RSA public key (N,e) and ciphertext c=m^e mod N, choose r←Z_N^* and compute c' = c·r^e = (m·r)^e mod N. If an oracle decrypts c' to m', then m = m'·r^{-1} mod N. r is invertible, so the blinding factor cancels modulo N; this is the algebra behind RSA blinding.

Why it matters

A cryptographic assumption usually says “no polynomial algorithm inverts on worst-case instances”; a real attacker only needs success on random instances. Random self-reduction connects the two worlds: success on average instances moves to any instance, and worst-case hardness spreads to random instances.

Blinding hides the message and makes decryption time independent of the ciphertext: multiply by random r^e, decrypt, then remove r at the end. A side-channel attacker sees intermediate values unrelated to the real m; this is the engineering use of random self-reduction.

Applications

  • Average-to-worst case: DL, RSA and CDH often use random self-reduction to turn worst-case assumptions into average-case ones. - Blinding: RSA decryption and signing blind before use to resist timing and chosen-ciphertext side channels. - Hardness amplification: repeat independent random instances to raise success δ to 1−(1−δ)^k, then choose parameters with error correction.

Reading: check that the randomization is a group homomorphism, the inverse map is computable, and the random-instance distribution is close to uniform.

Limits & attacks

  1. It needs algebraic structure. Randomization must preserve the instance’s homomorphic relation; an arbitrary OWF or hash has no such structure. 2. It needs an invertible blinding factor. RSA’s r must lie in Z_N^*; if r shares a factor with N, the inverse does not exist and blinding fails. 3. The oracle’s success is on average. If it succeeds only on some random instances, repetition can amplify success, but independence or a good distribution is needed. 4. It does not automatically give a concrete security bound. Blinding hides intermediate values but does not prove RSA secure; it moves the attack surface from “any instance” to “random instances”. 5. Group order and representation matter. Randomization for discrete log in composite-order or elliptic-curve groups takes a different form; rewrite the formula in the group operation.

Random self-reduction is a reduction tool, not a defence by itself. If the underlying problem is easy on random instances, blinding adds only constant overhead and does not change breakability.

History

Blum and Micali used the random self-reduction of discrete log in 1984 to build a pseudorandom bit generator: predicting the next bit on random instances would solve discrete log on any instance. Goldwasser and Micali described random self-reduction as the royal road from worst-case to average-case reductions.

RSA blinding entered implementations in the 1980s against timing attacks; chosen-ciphertext security and side-channel defences later made it a standard component. Random self-reduction remains the first step in proofs for DL/RSA-type assumptions.
