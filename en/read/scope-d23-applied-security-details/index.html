Principles

Domain: Applied Security Engineering.

Applied security concerns deployment in real systems: configuration, keys, protocol implementation, supply chain and user experience; one bad default can cancel a strong algorithm.

This page settles the 7 subtopics in this domain that do not yet have their own article:

  • Information Security Continuous Monitoring (信息安全持续监视): Continuous monitoring turns one-off compliance checks into ongoing observation of assets, vulnerabilities and configuration, with emphasis on measurement and traceability.
  • Security and Privacy Control Assessment (安全与隐私控制评估): Control assessment checks whether security and privacy controls are deployed as designed and effective, recording evidence and remediation in a closed loop.
  • Controlled Unclassified Information Protection (受控非密信息保护): Controlled unclassified information protection concerns how sensitive but unclassified data is classified, marked, transmitted and destroyed, often in defence supply-chain compliance.
  • Digital Identity and Authenticator Assurance (数字身份与认证器保证): Digital identity assurance evaluates identity proofing, authenticator strength and federation assertions separately, answering “why should this identity be trusted”.
  • format-preserving-encryption (Format-Preserving Encryption): Format-preserving encryption keeps the original format and length after encryption, common for database fields and payment card numbers; its security goals differ from ordinary block-cipher modes.
  • Systems Security Engineering and Cyber Resiliency (系统安全工程与网络弹性): Systems security engineering builds security and cyber resiliency into requirements, architecture, verification and operations rather than post-launch patching.
  • security-categorization (信息与系统安全分类): Security categorisation rates information and systems by impact of compromise and selects a control baseline; a wrong categorisation misaligns every later control.

Why it matters

These subtopics are kept on one page so that the domain boundary and a minimal definition exist before deciding which ones need independent deep entries. It avoids empty placeholders and avoids mistaking “has a name” for “has been explained”.

Key disputes

  1. Definition boundary: a domain label is a finding aid, not one theory. Merging adjacent entries hides differences in assumptions, models and adversary capability.
  2. Security boundary: catalog registration is not implementation security; standard clauses, parameters and side-channel exposure must be checked separately.
  3. Historical narrative: commemorative accounts of people, institutions and events do not replace primary archives; dates and priority still need item-by-item checking.

Limits & attacks

Boundary: this is a domain-level subtopic settlement page, not a full paper for each subtopic. A one-line definition states only what it belongs to and what problem it addresses; it does not replace a standard, textbook or paper. If an independent entry is created later, it must earn its own bilingual body and evidence review.

Do not mix in

  • Do not treat the domain page as a complete paper for every entry.
  • Do not treat the number of catalog registrations as the number of verified conclusions.
  • Do not treat commemorative narrative in historical entries as technical proof for the domain.
