SM4 Block Cipher Algorithm

Article review and catalog-metadata acceptance are recorded separately. The library remains under construction.

Principles

Standard: SM4 Block Cipher Algorithm (SM4 分组密码算法). ### Block and round function

SM4 uses a 128-bit block and 128-bit key over 32 rounds. Let the round state be X_i…X_{i+3}; then

X_{i+4}=X_i⊕T(X_{i+1}⊕X_{i+2}⊕X_{i+3}⊕rk_i),

where T(B)=L(τ(B)): τ applies the S-box to four bytes in parallel, and L(B)=B⊕(B≪2)⊕(B≪10)⊕(B≪18)⊕(B≪24). ### Key schedule

The initial K0…K3 is formed from FK constants and the key; round keys follow

rk_i=K_{i+4}=K_i⊕T′(K_{i+1}⊕K_{i+2}⊕K_{i+3}⊕CK_i),

with L′(B)=B⊕(B≪13)⊕(B≪23). Decryption uses the same structure with rk0…rk31 reversed. ### Modes and authentication

SM4 is only a block permutation; ECB hides no pattern, CBC needs a separate MAC, and CTR requires a non-repeating counter/IV. TLS 1.3 AEAD_SM4_GCM and AEAD_SM4_CCM use SM4 as the underlying block cipher under GCM/CCM rules.

Why it matters

SM4 obtains diffusion and confusion through 32 nonlinear rounds; its 128-bit block fits TLS, IPsec and cryptographic-module suites together with SM3 and SM2. Public standards and test vectors make it an interoperable baseline.

SM4 is a block cipher; SM3 is a hash and SM2 is an elliptic-curve public-key scheme. They are combined in protocols but have different security goals and are not substitutes.

Applications

  1. Choose a mode: use CBC+MAC or CTR+MAC for confidentiality without built-in authentication; use GCM/CCM for authenticated encryption. 2. Manage IVs: GCM IVs must be unique; CBC IVs may be public but should be unpredictable; CTR counters must not wrap. 3. Manage keys: round keys are expanded from the master key, which stays inside the module boundary. 4. Verify vectors: run standard test vectors and check reverse-key decryption.

Do not use ECB for multi-block messages; do not treat SM4 itself as a MAC; do not reuse a GCM key with a fixed IV.

Limits & attacks

  1. Mode misuse: ECB leaks block structure, CBC without a MAC permits padding/replay attacks, and CTR/GCM IV reuse breaks confidentiality or authentication. 2. Implementation leakage: table-based S-boxes and cache access are side-channel targets; fault injection can skip rounds or corrupt the last round. 3. Key management: plaintext master keys, unisolated round keys and open debug interfaces bypass algorithmic strength. 4. Overclaiming: SM4 has no known practical full-round classical attack, but that does not make every implementation secure; this entry is not implementation certification.

History

SM4 entered the domestic standard sequence as SMS4, moved into GM/T in 2012 and was published as GB/T 32907—2016 in 2016; it later entered ISO/IEC 18033-3 and became the block cipher behind the TLS 1.3 SM4 suites in RFC 8998 (2021).

Test vectors, modes and interface requirements can differ between editions; implementations follow the edition they claim, and this entry is not a clause-number substitute.
