HQC Alternative KEM

Article review and catalog-metadata acceptance are recorded separately. The library remains under construction.

Principles

Algorithm: Hamming Quasi-Cyclic (HQC 备选 KEM). HQC is a code-based KEM. The public key hides the structure of a quasi-cyclic code. Encapsulation selects a controlled-weight error vector and computes ciphertext under the public key. Decapsulation uses a decoder in the private key to recover the error vector and hash it into the shared secret. Its hardness assumption is decoding random linear codes, not lattices.

Why it matters

Post-quantum migration needs algorithm diversity. If lattices suffer a structural break, the ecosystem should not rest on one assumption. NIST selected HQC as a backup KEM in 2025 so the standard portfolio has a second independent path. Its keys and ciphertexts are larger, but its failure modes differ.

Applications

Backup KEM in standards drafts, protocol experiments and cross-implementation interoperability tests. It suits deployments that accept larger keys in exchange for algorithm diversity, rather than bandwidth-sensitive defaults.

Limits & attacks

The main risks are decoding failure rate, weak keys, side channels and parameter choice. An observable decoding failure can leak information; timing and cache behaviour can also be exploited. Shor's algorithm does not directly break it, but an unbroken code assumption is not the same as a secure implementation.

History

HQC entered the NIST post-quantum process in 2017 and went through several revisions. In March 2025 NIST selected HQC as a backup KEM, creating a lattice-and-code pair with ML-KEM. It is still moving through standardisation and should not be described as fully standardised.
