Principles

Algorithm: PLONK (PLONK 通用证明系统). ### Circuit proofs over a universal SRS

PLONK encodes an arithmetic circuit as gate constraints plus copy constraints: each gate is addition or multiplication, and a permutation argument enforces that the same wire carries the same value at different positions. The prover commits to wire values, permutation polynomials and quotient polynomials using a polynomial commitment (usually KZG); the verifier checks several openings. It uses a universal, updatable structured reference string (SRS): one parameter set can prove any circuit up to a size bound, instead of a fresh ceremony per circuit.

Why it matters

PLONK removes Groth16’s “one setup per circuit” problem. A universal SRS can be updated by a multi-party ceremony; security holds if at least one participant is honest, so developers can reuse parameters and iterate on circuits quickly.

Proofs remain constant-size and verification sublinear. Compared with Sonic, the prover performs far fewer group exponentiations, making PLONK practical to deploy.

Applications

PLONK and its variants (TurboPLONK, UltraPLONK, PlonKup) are used by Aztec, zkSync and other privacy/scaling projects; custom gates and lookup tables make hashes and range checks cheaper.

It is also the main entry point for engineering universal zk-SNARKs: Circom, Halo2 and snarkjs offer PLONK-style backends.

Limits & attacks

PLONK’s universal SRS is still a trusted setup: KZG relies on pairing groups and q-SDH-style assumptions, so it is not post-quantum. Proofs are constant-size but usually larger than Groth16, and verification is heavier.

The zero-knowledge argument of the original PLONK specification was later found incomplete; subsequent versions patched the simulator. Implementations must use the patched specification and enforce domain separation, challenge derivation and polynomial-commitment checks.

History

Ariel Gabizon, Zac Williamson and Oana Ciobotaru released PLONK as ePrint 2019/953 in 2019. The paper emphasizes “evaluations on a multiplicative subgroup rather than coefficients of monomials”, simplifying both the permutation argument and arithmetization.

TurboPLONK, UltraPLONK and PlonKup later added custom gates, lookups and faster proving; PLONK became the name of a broad family of universal SNARKs.
