Classic McEliece

The text and catalog metadata passed current review.

Principles

Algorithm: Classic McEliece (Classic McEliece 编码型公钥). Classic McEliece implements a Niederreiter KEM with binary Goppa codes: the public key is a systematic generator matrix T and the private key is a Goppa polynomial plus support; a ciphertext is a codeword plus an error vector of weight t, and private decoding recovers the session key. Concretely, T is a randomized systematic generator matrix; the private key contains the Goppa polynomial g, support alpha and a column permutation; encapsulation samples random m and computes c=T·m+e. ### Decoding

The private key uses Patterson decoding to find e in c and recover the codeword; a decapsulation failure yields an implicit rejection. Security rests on decoding random linear codes, not on lattices or number theory. ### Parameters

mceliece348864 has a 261,120-byte public key, 6,492-byte private key and 96-byte ciphertext; mceliece6688128 has a 1,044,992-byte public key and 208-byte ciphertext; the session key is 32 bytes.

Why it matters

McEliece is the most conservative post-quantum KEM: proposed in 1978, it has survived more than four decades of cryptanalysis without a practical full-parameter attack. Public keys are large but ciphertexts are small, which suits long-term identity keys and “one public key, many encapsulations”.

It does not rely on structured lattices, so its security assumption is independent of ML-KEM and useful for algorithm diversity and backup.

Applications

It serves long-term TLS/SSH/IPsec identity keys, code and firmware signing roots, and government/financial PQC migration; mceliece6688128 is often recommended as a long-term default. ISO standardized Classic McEliece in June 2026.

Requirements: public-key caching and transport dominate cost; constant-time private-key decoding; implicit rejection on failure; pc variants add 32 bytes to ciphertext; never use it as a PKE for arbitrary messages—it is a KEM.

Limits & attacks

Public keys can reach megabytes, amplifying certificate chains and handshakes; key generation is slow and complex; decoding failure rates, timing/cache attacks and fault injection are the main implementation risks.

Boundaries: McEliece encapsulates only a random key and does not encrypt user data; public-key reuse is by design, but the private key must be protected; parameter sets are tied to security levels and public keys/ciphertexts cannot be truncated; code-based and Goppa-structure cryptanalysis remain long-term concerns.

History

Robert McEliece proposed the McEliece public-key cryptosystem in 1978. The Classic McEliece team converted it into a Niederreiter-form KEM, entered the NIST PQC process and was selected by NIST for standardization; ISO standardized it in June 2026.

Parameters moved from the original 2^64 security to NIST levels 1/3/5, with public keys growing accordingly.
