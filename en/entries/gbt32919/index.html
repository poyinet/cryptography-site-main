SM2 Digital Signature

The text and catalog metadata passed current review.

Principles

Standard: SM2 Digital Signature (SM2 数字签名). ### Curve and keys

SM2 signatures use the 256-bit prime-field curve curveSM2 with base point G of order n. The private key is d∈[1,n−2] and the public key is P=dG. ### Signing

Compute e=SM3(Z_A‖M), where Z_A binds the user identity, curve parameters and public key. Choose random k∈[1,n−1], compute (x1,y1)=kG and

if r=0 or r+k=n, choose a new k. Then compute

s=((1+d)^{-1}(k−r d)) mod n;

if s=0, retry. The signature is (r,s). ### Verification

Check r,s∈[1,n−1]; set t=(r+s) mod n and reject if t=0; compute (x1,y1)=sG+tP and R=(e+x1) mod n; accept only if R=r.

Why it matters

SM2 binds the SM3 digest, curve arithmetic and user identity into one signing flow, fitting certificates, TLS authentication and electronic seals. Unlike ECDSA’s truncated x-coordinate, it closes the loop over e, r and s.

SM2 also defines public-key encryption and key exchange; this entry covers signatures only. SM3 is a hash and SM4 a block cipher, with different security goals.

Applications

  1. Generate keys: create d inside a cryptographic module and authenticate P by certificate or out-of-band channel. 2. Compute Z_A: use the standard ENTL, ID, curve parameters and public key; do not omit the identity. 3. Nonce: k must be unique and unpredictable, preferably from a DRBG or hardware source. 4. Verify: check the curve, point, order and r/s range before computing t and R.

Do not reuse k; do not skip Z_A; do not verify r without s; do not present SM2 as quantum-resistant.

Limits & attacks

  1. Nonce reuse: the same d and k over two messages exposes the private key; this is the most direct fatal error. 2. Missing curve/point checks: failing to verify that P lies on curveSM2 with the right order enables invalid-curve or small-subgroup attacks. 3. Side channels and faults: timing, cache access and fault injection in scalar multiplication can recover d; use constant-time code and redundancy. 4. Protocol layer: missing identity binding, domain separation or certificate chain lets a valid signature serve the wrong context.

History

SM2 was released in 2010, entered GM/T 0003 in 2012 and was published as the GB/T 32918 series in 2016; RFC 8998 (2021) uses SM2 signatures and curveSM2 in TLS 1.3.

Signature format, Z_A computation and curve parameters follow the claimed standard edition; this entry is not a clause substitute.
