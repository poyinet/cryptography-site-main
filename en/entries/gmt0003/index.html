GM/T 0003-2012 SM2 Public Key Cryptographic Algorithms

The text and catalog metadata passed current review.

Principles

Standard: GM/T 0003-2012 SM2 Public Key Cryptographic Algorithms (GM/T 0003-2012 SM2 椭圆曲线公钥密码算法). GM/T 0003-2012 divides SM2 into general, digital signature, key exchange, public-key encryption and parameter definition. Signing starts from a 256-bit prime-field curve E: y²=x³+ax+b mod p, base point G of prime order n, cofactor h=1; private key d_A∈[1,n-2] and public key P_A=[d_A]G. Before signing, ENTL_A, ID_A, a, b, x_G, y_G, x_A and y_A are bound into Z_A, and Z_A‖M is hashed into e. Choose k∈[1,n-1], compute (x1,y1)=[k]G and r=(e+x1) mod n; retry if r=0 or r+k=n. Then s=((1+d_A)^-1(k-r d_A)) mod n; retry if s=0 and output (r,s). Verification computes t=(r+s) mod n, rebuilds (x1,y1)=[s]G+[t]P_A, sets R=(e+x1) mod n and accepts only if R=r.

Why it matters

SM2 is not “ECDSA with another curve”. Z_A binds the user identity, curve parameters and public key into the signed input, so the same message yields different e under different identities or parameters; the (1+d_A)^-1 factor in s also differs from ECDSA’s k^-1 form.

Writing these formulas makes the separation between SM2 signing, encryption and key exchange explicit, and explains why range checks alone are insufficient: verification must rebuild R and reject t=0.

Applications

For signing, record the intermediate values in Z_A→e→k→r→s order and retry on any zero. Verification first checks r,s∈[1,n-1], then computes t and rejects t=0. For encryption, take the recipient public key P_B, choose k, compute C1=[k]G, S=[k]P_B, K=KDF(x2‖y2,klen), C2=M⊕K and C3=H(x2‖M‖y2); decryption checks C3 before recovering M.

Use the Part 5 p, a, b, n and G values; a homemade curve or altered base point breaks interoperability. Signing and encryption are domain-separated flows: a signature is not a ciphertext, and C1 is not a signature.

Limits & attacks

Reusing, predicting or sharing k across devices exposes the private key through repeated r; checking only r,s ranges without t≠0 can accept degenerate inputs. A wrong Z_A concatenation order, ENTL byte order or ID encoding breaks interoperability.

SM2 is a public-key system: certificates, name constraints and revocation still bind the key. Signing gives no confidentiality; encryption gives no signer authentication. Scalar multiplication, modular inversion and KDF must be constant-time against side channels.

History

SM2 was published in 2010 and issued on 2012-03-21 as the five-part GM/T 0003-2012, covering general, signature, key exchange, encryption and parameters; it became the GB/T 32918 series in 2016.

Part 5 lists the full hexadecimal p, a, b, n and G parameters plus signing, key-exchange and encryption examples; later GM/T 0009 and GM/T 0010 standardized SM2 usage and encrypted/signed message syntax.

Glossary

Z_A
a hash prefix binding the user ID, curve parameters and public key.
e
the digest of Z_A concatenated with message M, used to compute r.
r,s
the two scalar components of an SM2 signature; both are required.
KDF
the key-derivation function that expands shared point coordinates into a session key.
