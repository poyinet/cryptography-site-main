时间型一次性密码

本文和目录元数据已通过本轮复核。

原理与机制为什么重要应用与实例边界与攻击面历史与背景逐步示例与核验参考出处

原理与机制

术语：时间型一次性密码（TOTP）。RFC 6238 把 TOTP 定义为「extension of the… HMAC-based One-Time Password (HOTP) algorithm, as defined in [RFC4226], to support the time-based moving factor」，并要求「The algorithm MUST use HOTP [RFC4226] as a key building block」。核心关系是「TOTP = HOTP(K, T)」，其中「T = (Current Unix time - T0) / X, where the default floor function is used」；X 是以秒为单位的时间步（默认 30 秒），T0 是开始计步的 Unix 时间（默认 0，即纪元）。

为什么重要

把移动因子换成时间，双方无需同步计数器，但代价是必须容忍时钟偏差。§5.2 建议「at most one time step is allowed as the network delay」，并推荐 30 秒的时间步作为「a balance between security and usability」。§1.2 说明默认构造基于 HMAC-SHA-1（RFC 2104），同时允许「MAY use HMAC-SHA-256 or HMAC-SHA-512 functions … instead of the HMAC-SHA-1 function」。

应用与实例

实现要求为每个证明者使用唯一密钥：「There MUST be a unique secret (key) for each prover」，密钥「SHOULD be randomly generated or derived using key derivation algorithms」，密钥库「The key store MUST be in a secure area」，通信「SHOULD take place over a secure channel, e.g., … (SSL/TLS)」。§4.2 还要求实现「MUST support a time value T larger than a 32-bit integer when it is beyond the year 2038」。

边界与攻击面

强度来自底层 HOTP：§5.1 说「The security and strength of this algorithm depend on the properties of the underlying building block HOTP」，而 HOTP 的构造基于 HMAC 与 SHA-1；同一节也认为「the best possible attack against the HOTP function is the brute force attack」。时间窗口带来额外暴露：§5.2 警告「When an OTP is generated and exposed to a third party before it is consumed, the third party can consume the OTP within the time-step window」，因此要求「The verifier MUST NOT accept the second attempt of the OTP after the successful validation」以保证一次性使用。§6 给出偏差上限：接受两个时间步回退时，最大时间漂移约 89 秒。

历史与背景

RFC 6238「TOTP: Time-Based One-Time Password Algorithm」由 M’Raihi、Machani、Pei 与 Rydell 撰写，2011 年 5 月发布，类别为 Informational，并自我说明「not an Internet Standards Track specification」；它构建在 2005 年标准化的 HOTP（RFC 4226）之上，把计数器替换为时间。

术语小词典

HOTP
以计数器为移动因子的 HMAC 一次性口令算法。
TOTP
以时间步为移动因子的一次性口令算法。
时间步 X
把一个时间区间折算为一个计数值的秒数。
起始时间 T0
开始计算时间步的 Unix 时间。
验证窗口
允许偏差的时间步数。
共享密钥 K
证明者与验证者共有的秘密。
