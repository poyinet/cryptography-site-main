RSA 填充（PKCS#1）

本文和目录元数据已通过本轮复核。

原理与机制为什么重要应用与实例边界与攻击面历史与背景逐步示例与核验参考出处

原理与机制

术语：RSA 填充（PKCS#1）（RSA Padding (PKCS#1)）。PKCS#1 规定两种加密填充：RFC 8017 §7 写明「Two encryption schemes are specified in this document: RSAES-OAEP and RSAES-PKCS1-v1_5.RSAES-OAEP is REQUIRED to be supported for new applications; RSAES-PKCS1-v1_5 is included only for compatibility with existing applications.」填充把裸 RSA 置换包装成可用的加密方案，OAEP 是新实现的必选，v1_5 只为兼容旧应用而保留。

为什么重要

OAEP 的价值在于可证明的强度：§7.1 说明「Assuming that computing e-th roots modulo n is infeasible and the mask generation function in RSAES-OAEP has appropriate properties, RSAES-OAEP is semantically secure against adaptive chosen-ciphertext attacks.」附录 B.1 也用同一口径处理旧原语，称 MD2、MD5 与 SHA-1 只是为了兼容旧应用才被推荐。

应用与实例

文档给出典型用法：§7 称「A typical application is a key establishment protocol, where the message contains key material to be delivered confidentially from one party to another.」附录 C 则把参数写成硬约束，规定使用 id-RSAES-OAEP 时「parameters MUST be present and MUST be RSAES-OAEP-params」。

边界与攻击面

v1_5 填充的问题被写在 §7.2：「It is possible to generate valid RSAES-PKCS1-v1_5 ciphertexts without knowing the corresponding plaintexts, with a reasonable probability of success.This ability can be exploited in a chosen-ciphertext attack as shown in [BLEICHENBACHER].」同一节还写下实现层面的告诫「Care shall be taken to ensure that an opponent cannot distinguish the different error conditions in Step 3, whether by error message or timing.」，并说明否则对手可能「obtain useful information about the decryption of the ciphertext C, leading to a strengthened version of Bleichenbacher’s attack [BLEICHENBACHER]; compare to Manger’s attack [MANGER]」。文档并未把该填充标为已废除，只给出对策与不推荐用于任意消息加密的建议。

历史与背景

现行文本是 2016 年 11 月的 Version 2.2，头部标注「Obsoletes: 3447」且类别为 Informational；附录 D 记录演替：「Version 2.0 incorporated major editorial changes in terms of the document structure and introduced the RSAES-OAEP encryption scheme.」即 OAEP 是 2.0 版才进入 PKCS#1 的。
