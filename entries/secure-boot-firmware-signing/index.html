安全启动与固件签名

本文和目录元数据已通过本轮复核。

原理与机制为什么重要应用与实例边界与攻击面历史与背景逐步示例与核验参考出处

原理与机制

术语：安全启动与固件签名（Secure Boot & Firmware Signing）。NIST SP 800-193《Platform Firmware Resiliency Guidelines》把固件韧性拆成三类机制：Protection 是「Mechanisms for ensuring that Platform Firmware code and critical data remain in a state of integrity and are protected from corruption…」，Detection 是「detecting when Platform Firmware code and critical data have been corrupted or otherwise changed from an authorized state」，Recovery 是「restoring Platform Firmware code and critical data to a state of integrity…」，且恢复「is limited to the ability to recover firmware code and critical data」。§1.1 说明这层硬件与固件组合通常称为 platform。

为什么重要

执行摘要给出重要性判断：「Platform firmware, and its associated configuration data, is critical to the trustworthiness of a computing system.Much of this firmware is highly privileged in the system architectures, and because this firmware is necessary for the system to operate, repairing this firmware can be challenging」，并指出破坏可能「render a system inoperable, perhaps permanently or requiring reprogramming by the original manufacturer」。§2.2.1 因此规定「Firmware should only be loaded from an authorized source, typically either the manufacturer of the system or of the platform device」。

应用与实例

§3.1 的三类功能对应 §4.1 的信任根：Root of Trust for Update（RTU）、Root of Trust for Detection（RTD）与 Root of Trust for Recovery（RTRec）。§3.6.4 列出恢复的三种方式：「Fully automated」、「Partially automated」与「Manual」；§3.6.3 允许网络辅助恢复，但要求「if done in a secure and trustworthy manner, which may include the use of encryption, digital signatures, secure transport methods」。§3.2 要求平台被认为 Resilient 时所有 critical platform devices 都满足 §4 的指南。

边界与攻击面

信任根是薄弱点：§3.3 说明「The responsibility of ensuring the trustworthiness of a RoT is on the vendor which provides the Root of Trust」，而「A RoT must be designed to always behave in the expected manner … because its misbehavior cannot be detected」。§4.1.1 的指南要求「Information transferred from the software on the host processor to the platform firmware shall be treated as untrusted」。附录 B 把通用操作系统排除在固件范围外，也把外设列为 scope 之外。供应链侧的对应控制是「code authentication mechanisms, such as digital signatures, are implemented to ensure the integrity of software, firmware, and information」。

历史与背景

SP 800-193 由 Andrew Regenscheid 撰写，2018 年 5 月发布。执行摘要交代它的来历与扩展：「Earlier NIST publications have addressed the threat of attacks on one particular type of platform firmware: boot firmware, commonly known as the Basic Input/Output System (BIOS)」，而 §3.1 引用的 SP 800-147 正是 BIOS Protection Guidelines；本文件把范围从 BIOS 扩展到整平台的固件与关键数据。

术语小词典

平台固件
设备自带、先于操作系统运行的代码与配置数据。
关键数据
如启动顺序等被 §2.2.2.1 归入固件配置的数据。
RTU/RTD/RTRec
更新、检测与恢复三类信任根。
保护
保证固件代码与关键数据处于完整状态。
检测
发现代码或数据被非授权改动。
恢复
把固件回到可信状态的机制。
