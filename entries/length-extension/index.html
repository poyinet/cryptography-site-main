长度扩展攻击

原理与机制

攻击：长度扩展攻击（Length Extension Attack）。### Merkle–Damgård 状态

Merkle–Damgård 哈希把消息分块，用压缩函数 f 迭代链接值：h_i=f(h_{i−1},m_i)。最终摘要就是最后一轮的链接值；填充 pad=0x80||0…||len 把消息长度编码进最后一块。### 长度扩展伪造

给定 H(K||m) 和 K 的长度，攻击者把摘要当作链接值，直接继续压缩 m′，得到 H(K||m||pad||m′)，无需知道 K。若协议用 MAC=H(K||m) 且比较摘要，攻击者可追加任意消息并伪造有效 MAC。### HMAC 与海绵结构

HMAC 用 H((K⊕opad)||H((K⊕ipad)||m))，外层哈希遮蔽内层链接值，因而抗长度扩展；SHA-3 的海绵结构输出不是可直接续用的链接值，也不受影响。

为什么重要

这是“把哈希当 MAC”的经典错误：H(K||m) 看似密钥在前，实际把内部状态暴露给攻击者。它解释了为什么 HMAC 不是多此一举，也说明协议必须区分 hash、MAC、KDF 和签名原语。

应用与实例

给定 MAC=H(K||m) 与摘要，攻击者先猜 K 的长度、计算 pad，把摘要当作 IV 继续压缩 m′，得到 H(K||m||pad||m′)；把新消息与新摘要一起发给验证者即可通过。旧版 Flickr API、自定义 token 与“密钥前缀”文件完整性方案都出现过该问题。现代做法：HMAC、KMAC、BLAKE3 keyed mode、AEAD；若必须用 hash 构造 MAC，使用 HMAC 或先做长度编码与域分离。

边界与攻击面

受影响：MD5、SHA-1、SHA-256/512 等 Merkle–Damgård 哈希；不受影响：SHA-3/SHAKE、BLAKE2/3、HMAC、KMAC。SHA-384/512-256 的截断输出也不可直接扩展。

历史与背景

Merkle 1989 与 Damgård 1989 独立给出 MD 构造；1997 年 RFC 2104 标准化 HMAC 以修复密钥前缀 MAC 的缺陷；NIST SP 800-107r1 规范 HMAC 使用；SHA-3 海绵结构从根本上改变状态输出。它成为密码协议设计课的必修反例，也推动了 MAC 原语标准化。
