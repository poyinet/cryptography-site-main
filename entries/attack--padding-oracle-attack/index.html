填充预言攻击

本文和目录元数据已通过本轮复核。

原理与机制为什么重要应用与实例边界与攻击面历史与背景逐步示例与核验参考出处

原理与机制

攻击：填充预言攻击（Padding Oracle Attack）。填充预言攻击针对 CBC 模式：解密后接收方检查填充是否有效。攻击者修改前一个密文块，观察填充有效性，逐步恢复中间值和明文。

为什么重要

接收方通常会用确认或错误消息报告填充错误，这等于泄露一个填充是否有效的比特。Vaudenay 把这种泄漏称为侧信道，并表明一个比特足以驱动解密。按“输入 → 状态 → 变换 → 输出 → 判据”复述机制；每一步都要能指出谁执行、改变什么、留下什么证据。无法指出证据的步骤，只能标为待核，不能写成已复现。

应用与实例

论文把 SSL/TLS、IPsec、WTLS 等使用 CBC 和填充的标准列为应用场景；攻击者需要选择密文并能观察填充有效性。对 8 字节分组、256 字符表，平均约 1024N 次预言机调用可解密 N 个分组。

边界与攻击面

论文推荐的修复是先对填充后的明文做认证再加密；解密时先解密，再验证认证标签，最后检查填充。它指出仅让错误消息相同并不足以消除可区分性，也没有把认证密文或解密前认证作为修复。

历史与背景
